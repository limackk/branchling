# Security policy

## Supported versions

Before the first release, security reports are assessed against the current
`main` branch. After releases begin, only the latest published version and the
current `main` branch receive security fixes. Older releases, forks and
unmerged branches are not maintained security lines.

This policy identifies where a fix will be made; it does not promise a response
or release time.

## Reporting a vulnerability

Do not open a public issue or pull request for a vulnerability that has not
been disclosed yet. Use
[GitHub private vulnerability reporting](https://github.com/limackk/branchling/security/advisories/new)
instead. That report is visible only to the repository's maintainers until they
publish an advisory.

Include enough information to reproduce and assess the problem:

- the affected branch, release or commit;
- the impact and the conditions needed to trigger it;
- a minimal reproduction or proof of concept; and
- a suggested fix, if you have one.

Reports are assessed as maintainer availability permits. Please keep an
undisclosed vulnerability private while its impact and remedy are being
established. The maintainer will coordinate disclosure through the private
report, but this project does not promise a response, fix or disclosure date.

General bugs and support questions belong in the
[issue tracker](https://github.com/limackk/branchling/issues) and follow the
[support policy](SUPPORT.md).
