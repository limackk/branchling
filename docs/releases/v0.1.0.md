The first public release of branchling: a Git-native backlog for work done by
people and coding agents. Tasks are markdown files in your repository; the tool
hands them out one at a time, records who claimed each one and why it changed,
and refuses to close a task until its own verification commands pass.

## Install

```bash
npm install -g branchling
branchling --version
```

Or run it once without installing: `npx branchling --help`.

Requires Node 18 or newer. There are no runtime dependencies.

## First run

```bash
mkdir try-branchling && cd try-branchling && git init .
branchling init --dir backlog
branchling new --title "Write a README for a new user" --priority P1
branchling next --actor agent:claude
branchling done TASK-2
```

`init` writes a configuration, a template and one example task, and never
overwrites an existing file. The last command is expected to refuse: a new
task still carries the template's placeholder under `verification:`, and
`done` will not close a task that has no real contract. Replace the
placeholder with a command that proves the work, and `done` runs it and
closes the task only if it passes. The README walks through the same path, and
`docs/demo/scenario.md` records it with output.

## Supported platforms

| Platform | Status in 0.1.0 |
|---|---|
| Linux | Supported. CI runs the full suite on Node 18, 20 and 22. |
| macOS | Supported. CI runs the full suite on Node 18, 20 and 22. |
| Windows | **Not yet declared supported.** CI runs the full suite green on Node 22, but interactive use has not been vouched for. |

## Known limitations

- There is no hosted board, login or notification. Only people with a clone of
  the repository can see its backlog.
- branchling does not contain, choose or host agents. `branchling run` starts
  exactly the command you supply.
- The generated `viewer.html` is a read-only snapshot. Only the viewer served on
  loopback (`branchling` with no arguments) can write.

## Upgrade expectations

This is a 0.x release. The task file format, `config.yaml` keys and the `--json`
envelope may still change between minor versions; any such change will be named
in the release notes of the version that makes it, together with the command
that migrates an existing backlog where one is needed.
