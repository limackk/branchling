A minor release of branchling for teams that run several `branchling run`
loops at once, one per worktree of a clone. Loops no longer take tasks that
touch the same area, a paused loop leaves nothing half-claimed, and the locks
underneath them hold on Linux as they do on macOS. A project can now also
require its own checks before any task closes.

## Install or upgrade

```bash
npm install -g branchling@0.2.0
branchling --version
```

## Changes

### Parallel loops

- **Conflict groups** (TL-492). A task may name `conflict_group: [<name>]`, and
  `next` and `run` do not hand it out while a task of the same group is in
  progress in this tree or in another worktree of the clone. A project whose
  tasks name no group can set `conflict_group_from: epic` (or `board`,
  `labels`, `type`, `role`) in `config.yaml` to group them by that field. Skipped
  tasks are reported as `skippedConflict`.
- **`run --before-next <cmd>`** (TL-489) runs a gate before every hand-out; a
  non-zero exit stops the run before anything is claimed.
- **`run --commit-state`** (TL-489) commits only the task file and its history
  after each outcome, and refuses when anything else is staged.
- **`run --wait <s> [--wait-max <s>]`** (TL-491) keeps polling while the
  remaining tasks are held in other trees, instead of stopping with "the queue
  is empty". Without it, the stop now says how many tasks are held elsewhere.
- `branchling instructions autonomous-loop` describes the wrapper recipe for
  one loop per worktree.

### Closing

- **`closing_contract`** in `config.yaml` (TL-493, TL-495) lists verification
  entries that `done`, `probe` and `check --proofs` run after every task's own
  contract — repository-wide guards that a task's own tests can miss.
- **A question answered with `decide` returns its task to the queue** (TL-490),
  unowned, instead of leaving it in progress with nobody holding it.
- **A typed vouch needs a stated actor** (TL-460). `done` on a task with a
  `manual:` entry, at a terminal, refuses before running anything when no actor
  is given by `--actor`, the actor environment variable or the user config, so a
  person's confirmation is never recorded under the fallback agent name.

### Intake

- **`seed`** accepts `epic`, `role`, `executor`, `labels`, `related_docs` and
  `wave` per item (TL-493).
- **`plan add`** takes several ids in one call, all or nothing (TL-493).

### Correctness

- **Locks hold on Linux** (TL-494, TL-487). A stale mutex or an expired task
  reservation is removed only while its file still has the content that was
  judged; Linux reuses inode numbers immediately, so the inode alone could match
  a live writer's fresh file.
- **A living mutex holder is not taken over for being slow** (TL-488). A holder
  on the same host whose process still runs keeps its section past the 30 s
  stale limit, up to five minutes.
- **A backlog checked out with CRLF works like one with LF** (TL-479). `new`,
  field edits and history appends keep the line ending a file was checked out
  with.

## Upgrade notes

- `done` at a terminal on a task with a `manual:` entry now refuses when no
  actor is stated. Pass `--actor user:<name>`, set the actor environment
  variable, or put `actor:` in the user config. `--confirm-manual`, `--json` and
  runs without a terminal behave as before.
- New optional keys in `config.yaml`: `conflict_group_from`, `closing_contract`.
  Both are off unless set. A new optional task field: `conflict_group`; the
  shipped `_template.md` carries it as `conflict_group: []`.
- The `--json` envelopes of `run` and `next` gain keys (`skippedConflict`,
  `beforeNextRefused`, `stateCommitRefused`, `heldInOtherTrees`, `waited`); none
  that existed changed shape.
- Supported platforms are unchanged: Linux and macOS. The test matrix also runs
  Windows on Node 22, which is not yet a supported platform (TL-456).
